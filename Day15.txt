inner join :- returns matched records:-
======================================
returns matching values that have matching values in both tables
syntax:- 
select columns
from table1
inner join table 2
on table1.common_column-table2.common_volumn;


left join: left table all, right table matched to left table, remaining as null
========
returns all rows from the left table and the matched rows from the right table. If no match, null values appear from the right table column
syntax:- 
select columns
from table1
left join table2
on table1.common_column-table2.common_column;


right join:- right table all, left table matched to right  table, remaining as null
===========
returns all rows from the right table and the matched rows from the left table. If no match, null values appear from the left table column
syntax:- 
select columns
from table1
right join table2
on table1.common_column-table2.common_column;


Full Join
-----------
To simulate, use the Union of left join and Right Join

syntax
-------
select columns
from table1
left join table2
on table1.common_column=table2.common_column
union
select columns
from table1
right join table2
on table1.commom_column=table2.common_column;


Cross Join
-----------
returns cartesian product --> every row from the first table with every row from the second table.

syntax
-------
select columns
from table1
left join table2;

self join
-----------
select a.columns,b.columns
from table1 a
inner join table1 b
on a.commom_column=b.common_column;


views
------
what is a view
----------------
A view is a virtual table in MySQL. Built it from the result of stored select statement, it looks and behaves like regular table when you query it you can select from it, filter it and join i. but it does not store any data on its own. Every time a view is queried, MySQL runs its underlying select statement against in real tables and returns the result.

why do we need views
---------------------
To simplify complex queries.
reuse query logic
data security
logical data independence

Advantages of views
-------------
Security
reusability
simplicity
consistency
maintainability
custom data presentation
no extra storage cost.

creating views
----------------
create view view_name as 
select columns from table 
where condition.

altering views
----------------
alter view view_name as
select new_columns
from new_tables.

dropping view
---------------
drop view view_name;
drop view if Exists view_name;
